一键开关窗口：从 AppleScript 到 Swift

按一个快捷键：App 在前台就藏起来，不在前台就叫出来。为什么脚本版要等快一秒，换成 Swift 就几乎瞬间？

微信的command+shift+w开关非常爽，于是在想如何给其他软件配置快捷键。

说到快捷键，很容易就想到 skhd；说到窗口，很容易就想到 Yabai。skhd 是 macOS 上一个轻量的全局快捷键守护进程，配置文件里一行一条：修饰键 - 按键 : 要执行的命令；Yabai 是同一位作者写的平铺式窗口管理器。只是想“一个键开关一个 App”的话，用不上 Yabai，skhd 加一个小程序就够了。

1第一版：bash + osascript

一开始使用 skhd 绑定 bash ，然后用 osascript 调用窗口，但是这样启动 Applescript 的 AppleEvent 的引擎非常慢(开关快一秒了)，远不如Dock.app的 command+Tab ，旧代码如下

APP_NAME="$*"

ACTIVE_APP=$(osascript -e 'tell application "System Events" to get name of first application process whose frontmost is true')

if [ "$ACTIVE_APP" == "$APP_NAME" ]; then
osascript -e "tell application \"System Events\" to set visible of application process \"$APP_NAME\" to false"
else
open -a "$APP_NAME"
fi

逻辑很直白：$* 把所有参数拼成一个名字（所以 Google Chrome 带空格也行）；第一个 osascript 问 System Events 现在前台是哪个进程；如果就是目标 App，再起一个 osascript 让 System Events 把它设成不可见（效果和 ⌘H 一样）；否则交给 open -a，没开的会启动，开着的会被叫到前台。

慢在哪？每次按键都要现起一个 osascript 进程、装载 AppleScript 运行环境，再给另一个进程 System Events 发 Apple Event，等它在所有进程里找出前台那个，再把结果送回来；隐藏的时候这一套还要再来一遍。单说进程启动并不贵：在 macOS 15 上量一下，一个什么都不做的 osascript -e 'return 1' 大约 20 ms。既然两次启动加起来才几十毫秒，那“快一秒”的大头就花在和 System Events 的那两次往返上。

2第二版：编译成二进制

现在通过Swift编译二进制文件管理窗口：

swiftc -O ~/.config/skhd/toggle-app.swift -o ~/.config/skhd/toggle-app
import Cocoa

guard CommandLine.arguments.count > 1 else { exit(1) }
let targetAppName = CommandLine.arguments[1]
let workspace = NSWorkspace.shared

// 1. 获取当前最前台的 App
if let frontApp = workspace.frontmostApplication, frontApp.localizedName == targetAppName {
    frontApp.hide()
} else {
    if let targetApp = workspace.runningApplications.first(where: { $0.localizedName == targetAppName }) {
        targetApp.activate()
    } else {
        let task = Process()
        task.executableURL = URL(fileURLWithPath: "/usr/bin/open")
        task.arguments = ["-a", targetAppName]
        try? task.run()
    }
}

判断逻辑和脚本版一样，但每一步都是直接调 AppKit：NSWorkspace.shared.frontmostApplication 直接给出前台 App，runningApplications 是所有在跑的 App，hide()、activate() 是 NSRunningApplication 自己的方法。没有 AppleScript，也不经过 System Events，只有 App 没在跑的时候才去调一次 open -a。-O 是开优化；这段代码在 macOS 15 上直接编译通过，无参数的 activate() 是 macOS 14 起的写法。

编译好的二进制启动也快：同一台机器上，不带参数直接退出的 toggle-app 大约 4 ms（刚编译完第一次跑要几百毫秒，之后就稳定了）。

最后一种情况两边都要等 App 自己启动，差别就不大了；天天按的是前两种，省下的就是那将近一秒。

还有一个可能踩到的地方：localizedName 是 App 本地化后的显示名，系统语言不同，有的 App 显示名会变（比如变成中文），跟 skhdrc 里写的英文名就对不上了。遇到这种情况，可以改成比较 bundleIdentifier（比如微信是 com.tencent.xinWeChat），它不随语言变。

3接到 skhd 上

在skhd的配置 ~/.config/skhd/skhdrc 中调用 ：

ctrl + shift - w : ~/.config/skhd/toggle-app WeChat
ctrl + shift - c : ~/.config/skhd/toggle-app "Google Chrome"
ctrl + shift - a : ~/.config/skhd/toggle-app "Ghostty"

然后启动服务skhd --start-service，新版不能通过brew services start skhd启动了。

第一次启动时，skhd 需要在“系统设置 → 隐私与安全性 → 辅助功能”里打勾，才能收到全局按键。
