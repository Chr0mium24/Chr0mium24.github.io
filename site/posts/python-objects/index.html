Python 的对象模型：类、type 和元类

class 语句背后是谁在造类？obj.x 又是按什么顺序找到的？

这页的代码格都能改、能跑。点“运行”，浏览器会下载 Pyodide（编译成 WebAssembly 的 CPython），代码就在你自己的浏览器里执行，不经过任何服务器。同一页的代码格共用一个解释器，前面定义的东西后面能接着用。先从最经典的一行开始：

print("Hello World!")

1一切都是对象，类也是

在 Python 里，整数、字符串、函数、模块都是对象，类本身也是。每个对象都有一个类型，type(x) 告诉你它是被谁“造”出来的：type(5) 是 int，type("hi") 是 str。类既然也是对象，也就有类型——绝大多数类的类型是 type。

所以实例可以是一个类：所有 type 的实例都是类；反过来，判断一个东西是不是类，就看 isinstance(x, type)。

整个体系里有两个顶点，而且它们互相咬住：

  • object 是继承链的顶端，所有类都是它的子类；它自己也是一个类，所以 object 是 type 的实例。
  • type 是“是实例”这条链的顶端，所有类的类型最后都归到它；它自己也是类，所以 type 是 object 的子类。
  • type 的类型还是 type：它是自己的实例。

这个“鸡生蛋”的结构用 Python 代码写不出来，是解释器启动时在 C 层面直接搭好的。

print(isinstance(object, type))   # object 是 type 的实例
print(issubclass(type, object))   # type 是 object 的子类
print(type(object), type(type))   # 两个都是 type 造的，包括 type 自己
print(type.__mro__)
print(object.__mro__)

两个函数的规则都很短。isinstance(x, C)：先走一步虚线到 type(x)，再沿着 type(x).__mro__（实线往上）找有没有 C，所以 isinstance 支持继承传递（这里不算 __instancecheck__ 那种自定义钩子）。issubclass(A, C)：直接沿着 A 自己的 MRO 找，第一个参数必须是类。

开头那两句：

类是元类的实例，但不是元类的子类：

元类

元类就是“实例是类”的类，也就是 type 的子类。type 本身是最基本的元类；class Meta(type) 定义的是一个自定义元类。判断方法：issubclass(M, type)；等价地，如果一个类的 MRO 最后两项是 type、object，它就是元类。

2class 语句是 type(…) 的语法糖

type 有两种用法。传一个参数，type(x) 返回 x 的类型；传三个参数，type(name, bases, namespace) 当场造一个新类：name 是类名，bases 是基类的元组，namespace 是一个字典，会成为类的 __dict__。所以

class My_class:
    ...

基本等价于 My_class = type("My_class", (object,), {...})。元类也能这么造，只要基类里有 type：MyMeta = type("MyMeta", (type,), {...})。

class Dog:
    sound = "woof"
    def speak(self):
        return self.sound * 2

def speak(self):
    return self.sound * 2

Cat = type("Cat", (object,), {"sound": "meow", "speak": speak})

print(Dog().speak(), Cat().speak())
print(type(Dog), type(Cat))
print(Cat.__name__, Cat.__bases__, Cat.__dict__["sound"])

说“基本等价”，是因为 class 语句多做了几件事。按语言参考里“创建类对象”的描述，解释器遇到 class Person(Base, metaclass=M): 时：

  1. 定元类。候选是写明的 metaclass= 和每个基类的类型，取其中最“派生”的那个（它得是其余候选的子类，找不到就报 TypeError）；什么都没写、也没有基类，就是 type。
  2. 准备命名空间。调用 M.__prepare__(name, bases)，默认返回一个空字典。
  3. 执行类体。类体就是一段普通代码，在这个命名空间里跑一遍：赋值和 def 都变成字典里的键。
  4. 造类。调用 M(name, bases, namespace)，也就是先 M.__new__ 再 M.__init__。
  5. 绑定名字。有类装饰器先套上，再把结果赋给 Person。

3元类的 __new__：类在这里诞生

第 4 步是元类能插手的地方。重写元类的 __new__，就能在类诞生的那一刻看到（甚至改掉）它的名字、基类和类字典。跑一下：

# 类的 dict (在类定义结束时就有了)
class MyMeta(type):
    def __new__(cls, name, bases, attrs):
        print(f"1. 元类正在创建类 {name}")
        print(f"2. 传入的 attrs (即未来的类dict): {attrs.keys()}")
        # 此时 object.__new__ 还没运行
        return super().__new__(cls, name, bases, attrs)

class Person(metaclass=MyMeta):
    species = "Human"  # 进类的 dict
    def __init__(self, name):
        self.name = name # 进实例的 dict

print(f"3. 类创建完毕，查看 Person.__dict__: {Person.__dict__}")
# --- 实例的 dict (实例化时由 object.__new__ 产生) ---
print("4. 开始实例化...")
p = Person("Jack") # 触发 object.__new__
print(f"5. 实例 dict: {p.__dict__}")

几个值得看的地方：

  • 第 1、2 行在 class Person 这条语句执行时就打印了，那时还没有任何 Person 的实例。attrs 里有类体定义的 species、__init__，还有解释器塞进去的 __module__、__qualname__ 等。具体有哪些双下划线键随版本变：3.13 起多了 __firstlineno__ 和 __static_attributes__（后者记下了 self.name 这种在方法里赋值的属性名）。这页跑的是 Python 3.14。
  • 第 3 行的 Person.__dict__ 是 type.__new__ 拿 attrs 整理出来的：多了 __dict__、__weakref__、__doc__，__qualname__ 被收进了类型对象自己的字段，外面再套一层只读的 mappingproxy。
  • species 进类的字典，所有实例共享；self.name 进实例自己的字典，第 5 行只有 {'name': 'Jack'}。

造实例时走的是另一条链：Person("Jack") 其实是在“调用”一个对象，调用的是它的类型的 __call__，也就是 type(Person).__call__(Person, "Jack")。type.__call__ 里先调 Person.__new__ 拿到一个空对象（没写就是继承来的 object.__new__），如果拿到的确实是 Person 的实例，再调 __init__ 往里填东西：

class Meta(type):
    def __call__(cls, *args):
        print("Meta.__call__：要造一个", cls.__name__)
        obj = super().__call__(*args)    # 里面先调 __new__，再调 __init__
        print("Meta.__call__：造好了，交出去")
        return obj

class Point(metaclass=Meta):
    def __new__(cls, *args):
        print("  Point.__new__：分配一个空对象")
        return super().__new__(cls)
    def __init__(self, x, y):
        print("  Point.__init__：往里填 x、y")
        self.x, self.y = x, y

pt = Point(1, 2)
print(pt.__dict__)

元类能管“类怎么造”和“实例怎么造”两件事，但日常很少需要它：只想在子类定义时做点检查或登记，用 __init_subclass__（3.6 起有）；只想改一个类，用类装饰器。这两个都比元类好读。

4属性查找：obj.x 先看谁

先认识描述符：一个对象，如果它的类型定义了 __get__，它就是描述符。只定义 __get__ 的叫非数据描述符；还定义了 __set__ 或 __delete__ 的叫数据描述符。描述符只有放在类的字典里才起作用。

最常见的描述符其实是函数：所有函数都有 __get__ 方法，用于返回 bound method。obj.f 拿到的不是 C.f 那个函数本身，而是 C.f.__get__(obj, C)，一个把 obj 绑成第一个参数的方法对象。@property 则是数据描述符：property 类型总是带着 __set__ 和 __delete__，没写 setter 时调用它们会报错。

当你执行 obj.func 时，Python 内部逻辑（object.__getattribute__）是这样：

  1. 数据描述符优先：如果类里有 func（沿着 type(obj).__mro__ 找）且它是数据描述符（比如 @property），那就用类的，调它的 __get__。普通函数只有 __get__，没有 __set__，所以不属于这一条。
  2. 实例字典：如果在 obj.__dict__ 里找到了 func，直接返回这个值。关键点：哪怕这个值是个函数，有 __get__，也直接返回，不会绑定。
  3. 非数据描述符：如果实例里没找到，再看第 1 步在类里找到的东西：它有 __get__，这时候才触发绑定，返回 bound method。
  4. 类字典（无描述符）：类里有，但没 __get__，直接返回。
  5. 都没有：类里定义了 __getattr__ 就调它，否则抛 AttributeError。

同一个名字，实例字典里有没有同名值，结果可能完全不同：

class Data:                        # 数据描述符：有 __get__，也有 __set__
    def __get__(self, obj, cls):
        return "Data.__get__ 的返回值"
    def __set__(self, obj, value):
        raise AttributeError("只读")

class NonData:                     # 非数据描述符：只有 __get__
    def __get__(self, obj, cls):
        return "NonData.__get__ 的返回值"

class C:
    a = Data()
    b = NonData()
    c = "C 里的普通值"
    def f(self):
        return "方法"

obj = C()
print("实例里什么都没放：")
for name in "abcf":
    print(" ", name, "→", getattr(obj, name))

obj.__dict__.update(a="实例里的 a", b="实例里的 b", c="实例里的 c", f="实例里的 f")
print("实例里放了同名的：")
for name in "abcf":
    print(" ", name, "→", getattr(obj, name))

注意这里是用 obj.__dict__.update(...) 往实例字典里硬塞的。如果写 obj.a = "实例里的 a"，赋值同样会先看类里有没有数据描述符，有就调它的 __set__，这里会被“只读”拦下来。数据描述符能管住读和写两个方向，这正是 @property 能做只读属性、能做校验的原因。

在类上取属性（C.f）走的是 type.__getattribute__，规则同一个思路，只是“实例字典”那一步换成了沿 MRO 的各个类字典，描述符的 __get__ 收到的 obj 是 None。所以 C.f 拿到的就是函数本身。

5多继承：C3 线性化

第 1 步“沿 MRO 找”里的 MRO（method resolution order）是一张线性的列表：多继承的时候，Python 用 C3 算法把整棵继承图排成一条线，查属性、super() 都按这条线走。以下是手工计算 C3 MRO 的标准公式和步骤。

公式

假设类 C 继承自父类 \(B_1, B_2, \dots, B_n\)，即 class C(B1, B2, ...):。用 \(L(C)\) 表示类 C 的 MRO 列表：

\[L(C) = [C] + \operatorname{merge}\big(L(B_1),\ L(B_2),\ \dots,\ L(B_n),\ [B_1, B_2, \dots, B_n]\big)\]

  • [C]：C 永远在最前面。
  • \(L(B_i)\)：父类们各自的 MRO 列表（都以 object 结尾）。
  • \([B_1, \dots, B_n]\)：父类在定义时的原始顺序。这一项非常重要，保证了“局部优先顺序”：写在前面的父类在 MRO 里也在前面。

merge 的规则

先分清两个词：头是列表的第一个元素，尾是除了第一个以外的所有元素。

  1. 取出第一个列表的头 H。
  2. 检查 H 是否出现在其他任何列表的尾部：
    • 没有出现（H 是合法的）：把 H 放进结果，并从所有列表中删掉它，然后回到第 1 步。
    • 出现了（H 被别的列表“挡住”了：还有类必须排在它前面）：跳过这个列表，试下一个列表的头。
  3. 重复，直到所有列表都空了。
  4. 如果某一轮所有列表的头都被挡住（死锁），就抛 TypeError：无法创建一致的 MRO。

手算一个

class X: pass
class Y: pass
class Z: pass
class A(X, Y): pass
class B(Y, Z): pass
class M(B, A, Z): pass

已知 \(L(B) = [B, Y, Z, \text{object}]\)，\(L(A) = [A, X, Y, \text{object}]\)，\(L(Z) = [Z, \text{object}]\)。于是

\[L(M) = [M] + \operatorname{merge}\big([B, Y, Z, \text{obj}],\ [A, X, Y, \text{obj}],\ [Z, \text{obj}],\ [B, A, Z]\big)\]

看谁结论之后剩下
B不在任何尾部，取出[Y, Z, obj] [A, X, Y, obj] [Z, obj] [A, Z]
Y在 [A, X, Y, obj] 的尾部（被 X 挡住），跳过—
A第二个列表的头，不在任何尾部，取出[Y, Z, obj] [X, Y, obj] [Z, obj] [Z]
Y在 [X, Y, obj] 的尾部，跳过—
X不在任何尾部，取出[Y, Z, obj] [Y, obj] [Z, obj] [Z]
Y第二个列表里的 Y 是头不是尾，取出[Z, obj] [obj] [Z, obj] [Z]
Z取出[obj] [obj] [obj]
obj取出全空

最终结果：M → B → A → X → Y → Z → object。和解释器算的对一下：

class X: pass
class Y: pass
class Z: pass
class A(X, Y): pass
class B(Y, Z): pass
class M(B, A, Z): pass

print([k.__name__ for k in M.__mro__])

也可以把上面的规则原样写成代码，每取出一个类打印一次剩下的列表。改改 class M(...) 的父类顺序再跑：

def c3(cls):
    """照着上面的规则手算 L(cls)，每取出一个类打印一次"""
    seqs = [list(b.__mro__) for b in cls.__bases__] + [list(cls.__bases__)]
    out = [cls]
    show = lambda: "  ".join("[" + ", ".join(k.__name__ for k in s) + "]" for s in seqs if s)
    print("开始  ", show())
    while any(seqs):
        for s in seqs:
            if not s:
                continue
            head = s[0]
            if not any(head in t[1:] for t in seqs):
                break               # head 不在任何列表的尾部：可以取
        else:
            raise TypeError("所有列表的头都被挡住了，排不出一致的 MRO")
        out.append(head)
        seqs = [[k for k in s if k is not head] for s in seqs]
        print("取出", head.__name__, show())
    return out

class X: pass
class Y: pass
class Z: pass
class A(X, Y): pass
class B(Y, Z): pass
class M(B, A, Z): pass

mro = c3(M)
print([k.__name__ for k in mro], mro == list(M.__mro__))

排不出来的例子：P 要求 X 在 Y 前面，Q 要求 Y 在 X 前面，同时继承两者就矛盾了，类根本建不起来：

class X: pass
class Y: pass
class P(X, Y): pass    # 要求 X 在 Y 前面
class Q(Y, X): pass    # 要求 Y 在 X 前面
class R(P, Q): pass    # 两个要求矛盾

C3 保证的三件事也就清楚了：子类排在父类前面；同一个类的父类按书写顺序排；子类的 MRO 不会打乱父类 MRO 里已经定好的先后。super() 找的是这条线上的“下一个”，不一定是你以为的那个父类：在 M 的方法里调 super()，下一个是 B；在 B 的方法里（对象是 M 的实例时）再调 super()，下一个是 A，而 A 并不是 B 的父类。
