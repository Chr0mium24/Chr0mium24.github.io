抓一个小程序的 GraphQL 接口

小程序一页只给 10 条帖子、每条只带 3 条评论，接口到底是怎么分页的？

卡园是一个按学校分区的校园社区小程序：帖子挂在话题、子话题下面，可以匿名，可以带联系方式，有点赞和评论。随便写了一个渲染卡园json的parser，图像加载的缓存还没写。

数据是从小程序自己的请求里拿的。用proxifier抓微信小程序的包，改first,comment。

1抓包

微信小程序跑在微信客户端里，它发的请求不像网页那样能直接在浏览器开发者工具里看。Proxifier 的作用是把指定进程的网络连接强制转到一个代理上；代理那头放一个能解 HTTPS 的抓包工具（Charles、Fiddler、mitmproxy 这一类，需要先信任它的根证书），小程序的每个请求、每个响应就都能看到、能改、能重放了。

抓到的帖子列表请求是一个 POST，请求体里装着一大段 query Posts(...) {...}：这是 GraphQL。

2GraphQL 一分钟

REST 接口是“一个资源一个地址”；GraphQL 只有一个地址，客户端每次 POST 一段查询，在里面写清楚要哪些字段，服务端就只回这些字段。请求体通常长这样：

{
  "operationName": "Posts",
  "query": "query Posts($after: String, ...) { posts(...) { ... } }",
  "variables": { "after": null, ... }
}

下面第 4 节那段查询里有几样东西值得认一下：

  • query Posts($schoolId: ID, $after: String, ...)：声明变量，真正的值放在请求的 variables 里传。
  • fragment PostFields on Post { ... } 和 ...PostFields：片段，相当于把一组字段起个名字反复用。帖子、评论里的用户信息都用的是 ...UserFields。
  • 满屏的 __typename：每个对象的类型名。很多客户端库（比如 Apollo Client）会自动给每一层加上它，用来在本地缓存里区分对象。

3first 和 after：游标分页

列表字段 posts 用的是 Relay 风格的“连接”（connection）：

  • 参数 first: N 要前 N 条，after: 游标 从某个位置之后开始；
  • 返回的 edges 是一条条结果，每条的 node 才是帖子本身；
  • pageInfo 告诉你还有没有下一页（hasNextPage），以及这一页最后一条的游标（endCursor）；totalCount 是总条数。

翻页就是把上一页的 endCursor 原样填进下一次请求的 after，直到 hasNextPage 变成 false。游标对客户端来说是一个不透明的字符串，不用管它里面是什么。

小程序自己的查询把 first: 10 直接写死在查询文本里，没做成变量，所以“改 first”改的是请求体里的 query 字符串：

评论同理，每条帖子里嵌的 comments(first: 3, order: RANK) 只带排名前 3 的评论，totalCount 却是全部评论数：

first 不是想改多大就多大：服务端通常会给它设上限，太大可能报错，也可能悄悄截断，改完要对一下 totalCount 和实际拿到的条数。

写成代码就是一个 while 循环。下面用一个假的服务端（同样是示例数据）演示：

import base64

# 示例数据：23 条帖子，字段只留了 id 和 likeCount
POSTS = [{"id": f"post-{i}", "likeCount": (i * 7) % 11} for i in range(1, 24)]

def cursor(i):
    """graphql-relay 风格的游标：base64("arrayconnection:<下标>")"""
    return base64.b64encode(f"arrayconnection:{i}".encode()).decode()

def fake_server(first, after=None):
    """假装是服务端：按 first / after 切一页，返回和真接口同样形状的 JSON"""
    start = 0 if after is None else int(base64.b64decode(after).decode().split(":")[1]) + 1
    page = POSTS[start:start + first]
    end = start + len(page) - 1
    return {"data": {"posts": {
        "totalCount": len(POSTS),
        "edges": [{"node": p} for p in page],
        "pageInfo": {"hasNextPage": end < len(POSTS) - 1,
                     "endCursor": cursor(end) if page else None},
    }}}

after, n = None, 0
while True:
    posts = fake_server(first=10, after=after)["data"]["posts"]
    n += 1
    ids = [e["node"]["id"] for e in posts["edges"]]
    print(f"第 {n} 次 after={after}: {ids[0]} … {ids[-1]}（{len(ids)} 条）")
    if not posts["pageInfo"]["hasNextPage"]:
        break
    after = posts["pageInfo"]["endCursor"]

print("一共", posts["totalCount"], "条，请求了", n, "次")

4完整查询

抓到的帖子列表查询（带下划线的几行能点，图会跟着变）：

query Posts(
  $schoolId: ID
  $topicId: ID
  $subtopicId: ID
  $keyword: String
  $orderBy: PostOrder
  $after: String
  $excludeTopicId: ID
  $rankFilter: RankFilter
) {
  posts(
    filter: {
      schoolId: $schoolId
      topicId: $topicId
      subtopicId: $subtopicId
      keyword: $keyword
      excludeTopicId: $excludeTopicId
      rankFilter: $rankFilter
    }
    orderBy: $orderBy
    first: 10
    after: $after
  ) {
    edges {
      node {
        ...PostFields
        __typename
      }
      __typename
    }
    totalCount
    pageInfo {
      hasPreviousPage
      hasNextPage
      startCursor
      endCursor
      __typename
    }
    __typename
  }
}
