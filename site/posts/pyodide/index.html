在浏览器里跑 Python

micropip 报“找不到纯 Python 3 wheel”的时候，到底卡在哪个包上？

1Pyodide：浏览器里的 CPython

Pyodide 是用 Emscripten 把 CPython 解释器整个编译成 WebAssembly 的项目：解释器、标准库一起下载到浏览器，代码在本地执行，不需要后端。PyScript 在它上面又包了一层，让你在 HTML 里直接写 Python；底层跑的还是 Pyodide，装包也一样交给 micropip，所以下面说的坑两边是同一个。

这页的代码格就是这么跑起来的，每一格都用一个全新的解释器，互不影响：

import sys
print(sys.version)
print(sys.platform)    # 不是 linux / darwin，而是 emscripten

2包从哪来

Python 包发布成 wheel，文件名最后三段是“标签”：比如 lcapy-1.26-py3-none-any.whl 的 py3-none-any 表示纯 Python、不挑平台，放进 WebAssembly 里也照样能用；而带 C 扩展的包（numpy、scipy…）在 PyPI 上只有给 Linux、macOS、Windows 编译的版本，浏览器里一个也跑不了。

所以 Pyodide 自己维护了一个发行版：把常用的 C 扩展包用 Emscripten 重新编译好，放在 CDN 上，比如这页用的 314.0.7 版里是 numpy-2.4.6-cp314-cp314-pyemscripten_2026_0_wasm32.whl。装包有两条路：

  • JavaScript 里 await pyodide.loadPackage([...])：只认发行版里的包，按发行版的清单把依赖一起装上。
  • Python 里 await micropip.install(...)：对每个要装的包（默认还有它声明的所有依赖，一层层往下）依次问：
    1. 已经装了吗？装了就跳过；
    2. Pyodide 发行版里有吗？有就从 Pyodide 的 CDN 装；
    3. PyPI 上有纯 Python 的 wheel 吗？有就下载；
    4. 都没有：报错。micropip 不会、也没法在浏览器里从源码包编译。

第 4 种情况的报错就是这一句：

ValueError: Can't find a pure Python 3 wheel for 'importlib'.
See: https://pyodide.org/en/stable/usage/faq.html#why-can-t-micropip-find-a-pure-python-wheel-for-a-package
You can use `await micropip.install(..., keep_going=True)` to get a list of all packages with missing wheels.

3lcapy 卡在 importlib

lcapy 是一个做线性电路符号分析的库，本身是纯 Python 的 wheel。但 2025-09-28 发布的 1.26 版在依赖列表里多写了一项 importlib。PyPI 上叫 importlib 的包是给 Python 2.7 用的 import_module() 移植版，只有一个源码包 importlib-1.0.4.zip，没有任何 wheel。Python 3 的 importlib 是标准库，根本不用装。

在普通电脑上，pip 会把这个源码包构建一遍，在 Python 3 上它什么文件都不装，只留下一个 dist-info，相安无事；到了 micropip 这里，没有 wheel 就是死路，于是整个 install 在解析阶段就失败了，lcapy 本身也没装上。

deps 开着的时候，预装什么都没用，importlib 那一行永远过不去：

想看看这一行的报错，直接让 micropip 装 importlib 就能复现：

import micropip
await micropip.install("importlib")

报错末尾提示可以加 keep_going=True。它只会把所有找不到 wheel 的包一次列全（这里只有 importlib 一个），并不会让安装成功。

4deps=False，依赖自己装

关键代码：

outputElement.innerText += '\n正在安装 lcapy...';
await pyodide.runPythonAsync(`
    import micropip
    await micropip.install('lcapy',deps=False)
`);

当频繁出现上面那种报错、这类下载不到官方库的抽象问题时，并不要去keep_going=True，而是应该自己加载好所有的依赖await pyodide.loadPackage(["numpy", "scipy", "sympy", "matplotlib", "networkx"])，忽略原来提供的包依赖deps=False。

deps=False 让 micropip 只装 lcapy 自己那一个 wheel，依赖列表整个不看；真正要用的 numpy、sympy 这些，提前用 loadPackage 从 Pyodide 发行版装好。顺带也跳过了几个在网页里用不上的依赖：IPython 只在 Jupyter 里显示电路图时才用到，property-cached 只是给 Python 3.8 以前准备的后备。

只关依赖、不补包，装是能装上，import 就出事了：

import warnings
warnings.simplefilter("ignore", SyntaxWarning)   # lcapy 源码里有几处无效转义，3.12 起编译时会警告

import micropip
await micropip.install("lcapy", deps=False)
import lcapy

那到底要补哪几个？在 Pyodide 314.0.7 里把它们一个个去掉试一遍：import lcapy 时会依次用到 sympy、numpy、networkx，缺哪个就在哪儿报 ModuleNotFoundError；scipy 是 lcapy 里某些函数用到时才导入的，不装也能 import、能解简单的电路；matplotlib 则不用操心，装 networkx 时发行版会顺带装上。

五个都装是最稳的做法，代价是下载量：发行版会把它们的依赖一起拉下来，一共 18 个包、30 多 MB，光 scipy 就 14 MB。下面这格就是完整流程，第一次跑要等一会儿：

import warnings
warnings.simplefilter("ignore", SyntaxWarning)

import micropip, pyodide_js
await pyodide_js.loadPackage(["numpy", "scipy", "sympy", "matplotlib", "networkx"])
await micropip.install("lcapy", deps=False)

from lcapy import Circuit
cct = Circuit("""
V1 1 0 {u(t)}
R1 1 0 1k
E1 2 0 1 0 5
R2 2 0 1k
""")
print(cct[2].v)    # 压控电压源把 V1 放大 5 倍

Python 里的 pyodide_js 就是 JavaScript 那边的 pyodide 对象，pyodide_js.loadPackage 和上面 JS 里的 pyodide.loadPackage 是同一个函数。电路本身的写法见四种受控源。

5碰到这类报错时

  1. 看报错里点名的那个包是谁要的。PyPI 的 JSON 接口能直接看到一个包声明的依赖：https://pypi.org/pypi/lcapy/json 里的 info.requires_dist。
  2. 点名的包如果像 importlib 这样根本用不上（Python 2 的移植版、Windows 专用的包、只给命令行用的工具……），就 deps=False 绕过去。
  3. 剩下真正要用的依赖，发行版里有的用 loadPackage 装，没有的再单独 micropip.install（它们自己的依赖照常解析）。
  4. 跑一遍 import 和你要用的函数。deps=False 的坑不会在安装时出现，而是在用到某个模块时才冒出 ModuleNotFoundError，缺什么补什么。
