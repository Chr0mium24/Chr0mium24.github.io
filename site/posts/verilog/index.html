Verilog 入门：wire、reg 和时钟

写的明明是代码，描述的却是电路：assign 和 always 到底差在哪？

学 Verilog 最先要扭过来的一点：它不是一行一行往下执行的程序，而是在描述一块电路。每一条 assign、每一个 always 块都是一块同时在工作的硬件，写在前面还是后面没有区别。下面按“文件 → 模块 → 语法 → 赋值 → 建模”的顺序过一遍。

0文件类型

有 .v 和 .sv 两种文件，分别是 Verilog 和 SystemVerilog。两者的关系类似 C 和 C++：SystemVerilog 是 Verilog 的超集，加了面向对象（主要给写测试平台用）、更多的系统函数、logic 类型、断言等。Verilog 里的运算符和流程控制语句（if、case、for）也和 C 很像，读起来不陌生。

1模块和端口

模块（module）是 Verilog 的基本单位，相当于一块芯片：外面一圈是端口，里面是功能。

module and_gate (
  input  a,       // 输入端口 a
  input  b, c,      // 当然你也可以写一起
  output out      // 输出端口 out
);
  assign out = a & b; // 描述功能：out 是 a 和 b 的与运算结果

endmodule

端口有三个方向：input、output，以及双向的 inout（比如总线）。端口可以带位宽和类型：

module example (
  input             clk,       // 1位的输入,未标注reg默认类型为wire
  input logic [7:0]      data_in,   // 8位的输入总线 (位宽为8)
  output            valid,     // 1位的输出
  output reg [15:0] data_out,  // 16位的寄存器型输出
  inout [3:0]       bus        // 4位的双向总线
);

[7:0] 表示 8 根线，编号从高到低是 7 到 0，左边是最高位。logic 是 SystemVerilog 的写法，放在 .sv 文件里。

wire、reg、logic

  • wire 是导线，用于组合逻辑。它自己不存值，值由驱动它的东西（逻辑门、assign 语句）时时刻刻决定。
  • reg 用在 always 或 initial 块里赋值的信号，它会保持一个值，直到被重新赋值。在 always @(posedge clk) 里赋值时，它综合出来就是触发器，一个真正的存储元件；但在 always @(*) 中被赋值时，reg 将变为类似 wire 的组合逻辑。所以“reg”这个名字并不保证真有寄存器，看的是它在什么样的 always 里被赋值。
  • logic 在 SystemVerilog 中被引入，是 wire 和 reg 的综合：用 assign 驱动还是在 always 里赋值都行，由用法决定它是什么。

每一位信号除了 0 和 1，还可能是 x（不确定，比如还没被赋过值的 reg）和 z（高阻，没人驱动，比如释放了的 inout 总线）。仿真波形里那段斜纹就是 x。

2基础语法

字面量

写法是 <位宽>'<进制><数值>，左边是高位，右边是低位。进制有 b（二进制）、o、d、h（十六进制），比如 4'b1010、8'hFF、16'd300。花括号把几段拼成一段：

wire [3:0] high_nibble = 4'b1010; // "nibble" 指4位
wire [3:0] low_nibble  = 4'b1100;
wire [7:0] byte_data; assign byte_data = {high_nibble, low_nibble};// 将两个4位信号拼接成一个8位信号 10101100

常量

parameter 可以在实例化时被外部重写（override），适合写“可配置位宽”的模块：

module memory #(
    parameter DATA_WIDTH = 8, // 定义一个可修改的参数
    parameter ADDR_WIDTH = 10
) (
    // ...
);
    // ...
endmodule

// 在实例化时，我们可以修改 DATA_WIDTH
// 创建一个16位宽的内存
memory #(
    .DATA_WIDTH(16)
) mem_inst (
    // ...
);

localparam 是局部常量，外部无法修改，通常给 case 语句当标签，代替一个个裸的数字：

localparam ADD = 2'b00;

always @(*) begin
    case (op_sel)
        ADD: result = a + b; // 使用 localparam 提高可读性
        // ...
    endcase
end

几个容易混的地方：& 是逐位与，结果和操作数一样宽；&& 是逻辑与，结果只有 1 位。单独放在一个信号前面的 &a、|a、^a 叫归约运算，把 a 的所有位与/或/异或成 1 位，比如 ^a 就是奇偶校验位。<= 在表达式里是“小于等于”，在 always 里当语句用是非阻塞赋值，靠位置区分。$countones（数 1 的个数）是 SystemVerilog 的系统函数，用 Icarus Verilog 仿真要加 -g2012。

3赋值：assign 和 always

wire 用 assign 连续赋值：右边任何一个信号变了，左边立刻跟着变，就像一根导线接在门电路的输出上。reg 用 initial 或 always 过程赋值，又分两种：

阻塞赋值 =：立即执行并完成赋值，下一行看到的就是新值，和普通编程语言一样。

// 阻塞赋值 (组合逻辑)
always @(*) begin
  b = a;
  c = b; // 这里的 b 是已经被 a 赋值后的新值
end

非阻塞赋值 <=：右边的表达式先全部算好，赋值推迟到整个块结束时同时发生，行为是并行的。

// 非阻塞赋值 (时序逻辑)
always @(posedge clk) begin //(posedge: 上升沿触发，negedge: 下降沿触发)
  q1 <= d; // 在时钟上升沿，计算 d 的值
  q2 <= q1; // 同时，计算 q1 的旧值
           // 在块结束时，q1 更新为 d 的值，q2 更新为 q1 的旧值
           // 这会形成一个两级触发器
end

下面这张图把两种赋值放在同一个模块里：y 是 assign 出来的组合输出，q1、q2 是挂在时钟上的寄存器。

几个值得点的情形：

看完就明白为什么有那条经验规则：时序逻辑（always @(posedge clk)）里用 <=，组合逻辑（always @(*)）里用 =。时钟块里用 =，结果会依赖语句的先后顺序，几个寄存器之间的“晚一拍”关系就没了；而且多个 always 块之间还会出现仿真竞争，仿真和综合出来的电路对不上。

always @(*) 和锁存器

注意：尽管从最终生成的硬件电路的角度来看，always @(*) 块和使用 assign 驱动的 wire 是等价的，但是 always 存在产生额外锁存器的风险，而且写法的层级和 assign 不同（一个是过程块里的语句，一个是模块里的连续赋值）。

// 这个代码会生成一个锁存器！
always @(*) begin
      if (enable == 1'b1) begin
          q = d;
      end
      // 问题：当 enable 不等于 1 时，没有告诉 q 应该是什么值！
      // 综合器会认为：q 必须保持它之前的值，因此需要一个锁存器来存储它。
end
// 修正：为所有分支都提供赋值
always @(*) begin
    if (enable == 1'b1) begin
        q = d;
    end else begin
        q = 1'b0; // 或者 q = d_default_value;
    end
end

另一个常用的写法是在 always 块第一行先给所有输出一个默认值，后面的 if、case 只改需要改的，漏写分支也不会多出锁存器。case 语句同理，记得写 default。

何时使用 always @(*)：当逻辑很复杂，需要用到 if-else 或 case 语句来提高代码可读性时，例如解码器、算术逻辑单元（ALU）、状态机的组合逻辑部分等，可以像写高级语言一样描述复杂的逻辑。但仍需确保所有 reg 在所有代码分支中都被赋值，以避免意外生成锁存器。

4建模思想

同一个电路可以从三个抽象层次来描述。以全加器（a + b + 进位 c_in，输出和 sum、进位 c_out）为例：

行为级（Behavioral）

直接写“它做什么”，电路怎么搭交给综合器：

assign {c_out, sum} = a + b + c_in;

数据流（Dataflow）

写出信号之间的逻辑关系：

assign sum = a ^ b ^ c_in;
assign c_out = (a & b) | (b & c_in) | (a & c_in);

结构级（Structural）

像搭积木一样，把现成的模块实例化、用线连起来：

// 首先需要一个半加器模块
module half_adder(input a, b, output s, c);
    assign s = a ^ b;
    assign c = a & b;
endmodule

// 然后用结构化方式搭建全加器
module full_adder_struct(
    input a, b, c_in,
    output sum, c_out
);
    wire s1, c1, c2; // 定义内部连线

    // 实例化第一个半加器
    half_adder ha1 (
        .a(a),
        .b(b),
        .s(s1),
        .c(c1)
    );

    // 实例化第二个半加器
    half_adder ha2 (
        .a(s1),
        .b(c_in),
        .s(sum),
        .c(c2)
    );

    // 用一个或门连接两个进位
    or U1 (c_out, c1, c2);

endmodule

.a(a) 这种写法叫按名字连接：点后面是子模块的端口名，括号里是这一层的信号。最后一行的 or 是 Verilog 内置的门原语，第一个参数是输出。三种写法描述的是同一个全加器，把 8 种输入组合都喂进 Icarus Verilog 跑一遍，三个模块的输出完全一致。

建模级别核心思想主要关键字/语法抽象程度
行为级描述电路的功能、算法always、initial、if-else、case、+最高
数据流描述数据在电路中的流动和变换assign、逻辑运算符中等
结构级描述电路的构成和连接模块实例化 module_name inst_name (...)最低

实际项目里三种经常混着用：顶层用结构级把模块连起来，模块内部用 assign 和 always 写。
