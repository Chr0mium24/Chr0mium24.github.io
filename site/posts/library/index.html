某图书管理系统的分析

接口给的是毫秒时间戳，几点哪间房空着？

这是一个图书馆研讨间、安静室预约系统的查询接口：查占用情况就是一个 GET 请求，带上登录后的 cookie，直接返回 JSON。下面这段 Python 一次把某天某类房间的预约全拉下来，换算成几点到几点。

只做了读，预订还没折腾，cookie的自动化获取有、麻烦

代码做的事就两步：按日期和房间类型请求预约列表，再把每条预约的开始、结束时间从毫秒时间戳换成 GMT+8 的几点。换完以后，空房就是时间轴上没被占的那几段。

1接口长什么样

请求只有一个地址，参数都在查询串里：

  • resvDates：要查的日期；
  • kindIds：房间类型的编号，代码里写死了四种（新旧两个馆 × 安静室、小组研讨室）；
  • page、pageSize=30：分页，一类房间超过 30 间就得翻页；
  • sysKind=1、labId=：固定不变。

返回的 JSON 里 code == 0 且 message == "查询成功" 算成功，data 是房间列表，每间房有房间号 roomSn 和预约列表 resvInfo，每条预约的 startTime、endTime 是毫秒时间戳。身份只靠请求头里的 ic-cookie，代码里留了一个 IC_COOKIE 变量，要自己从登录后的浏览器里复制进去。

2时间戳怎么变成几点

接口里的 startTime 是毫秒。代码里的 timestamp_to_gmt8_time_of_day 先除以 1000，按 UTC 读出来，再换到 GMT+8，最后只留时分秒。

3代码

Python（请求和解析） 
import requests
import json
from datetime import datetime
import pytz
IC_COOKIE = ""
def timestamp_to_gmt8_time_of_day(timestamp_ms):
    """
    将毫秒级时间戳转化为 GMT+08:00 时区一天里的几点。

    Args:
        timestamp_ms: 毫秒级时间戳。

    Returns:
        一个字符串，表示 GMT+08:00 时区一天里的几点，格式为 "HH:MM:SS"。
        如果输入不是数字或无法转换，则返回 None。
    """
    try:
        # 将毫秒转换为秒
        timestamp_sec = timestamp_ms / 1000.0
        # 创建 UTC 时间的 datetime 对象
        utc_datetime = datetime.utcfromtimestamp(timestamp_sec)
        # 获取 GMT+08:00 时区
        gmt8_tz = pytz.timezone('Etc/GMT-8')  # 注意：pytz 中 GMT+08:00 可能表示为 'Etc/GMT-8' 或 'Asia/Shanghai' 等
        # 将 UTC 时间转换为 GMT+08:00 时间
        gmt8_datetime = utc_datetime.replace(tzinfo=pytz.utc).astimezone(gmt8_tz)
        # 格式化为一天里的时间
        time_of_day = gmt8_datetime.strftime('%H:%M:%S')
        return time_of_day
    except (TypeError, ValueError):
        return None
        
def fetch_room_reservations(date,kind):
    """
    Fetches room reservation data from the given URL and extracts occupied times.

    Args:
        url (str): The URL to fetch the reservation data from.

    Returns:
        dict: A dictionary where keys are room names and values are lists of
              occupied time slots (start and end times in milliseconds).
    """
    kindid = {
        "oldlib_quietroom":101766982,
        "oldlib_groupstudyroom":101420505,
        "newlib_quietroom":101505911,
        "newlib_groupstudyroom":100462149,
    }[kind]
    url = f"https://librooms.cuhk.edu.cn/ic-web/reserve?sysKind=1&resvDates={date}&page=1&pageSize=30&kindIds={kindid}&labId="
    try:
        headers={'Cookie':'ic-cookie=IC_COOKIE'}
        response = requests.get(url,headers=headers)
        response.raise_for_status()  # Raise an exception for bad status codes
        data = response.json()
        if data.get("code") == 0 and data.get("message") == "查询成功":
            reservations = {}
            for room in data['data']:
                room_name = room['roomSn']
                for reserve in room['resvInfo']:
                    if not reservations.get(room_name):
                        reservations[room_name]=[]
                    reservations[room_name].append({'startTime':timestamp_to_gmt8_time_of_day(reserve['startTime']),'endTime':timestamp_to_gmt8_time_of_day(reserve['endTime'])})
            return reservations
        else:
            print(f"Error: {data.get('message')}")
            return None
    except requests.exceptions.RequestException as e:
        print(f"Request error: {e}")
        return None
    except json.JSONDecodeError:
        print("Error decoding JSON response.")
        return None

4几处可以改的地方

  • cookie 没传进去。headers={'Cookie':'ic-cookie=IC_COOKIE'} 发出去的是字面上的 “IC_COOKIE” 这几个字母，要写成 f'ic-cookie={IC_COOKIE}' 才是变量的值。
  • 全天空着的房间不会出现在结果里。字典的键是在遍历 resvInfo 时才建的，一条预约都没有的房间循环一次都不跑，结果里就没有它，而这恰恰是最想找的房间。先 reservations[room_name] = [] 再遍历就好。
  • utcfromtimestamp 已经不推荐了。Python 3.12 起 datetime.utcfromtimestamp 会报弃用警告。不用 pytz 也能一步到位：datetime.fromtimestamp(ms / 1000, tz=timezone(timedelta(hours=8)))。
  • docstring 和返回值对不上。说明里写返回“毫秒的开始、结束时间”，实际返回的是 "HH:MM:SS" 字符串；只留时分秒，跨天的预约也就分不出来了。
